La agenda y los pagos de BeSalud, dentro de la web de tu consultorio

Tus pacientes se registran, eligen horario, pagan el abono y gestionan sus citas sin salir de tu página. BeSalud pone la agenda, las reservas y la pasarela de pagos; tú pones tu diseño.

Empezar Referencia de la API Probar en vivo

Cómo funciona

  1. verified_user

    1. Activamos tu dominio

    Un administrador vincula la dirección de tu web a tu cuenta de médico. Solo ese dominio puede usar tu agenda.

  2. integration_instructions

    2. Pegas dos líneas

    El widget dibuja el registro, los horarios, el pago y "Mis citas" con los colores de tu sitio. O usas la API directamente.

  3. event_available

    3. Tus pacientes agendan

    Las citas llegan a tu panel de BeSalud como cualquier otra, con el abono ya pagado.

Empieza en 2 minutos

Pega el script antes de cerrar </body> y marca los botones que abren la agenda. Cambia mi-consultorio por el identificador que ves en tu panel, en la sección Mi página web.

HTML 
<script src="https://api.besalud.co/widget/besalud-widget.js"
        data-consultorio="mi-consultorio" defer></script>

<a href="#" data-besalud="agendar">Agendar cita</a>
<a href="#" data-besalud="mis-citas">Mis citas</a>

Con tus colores

El widget vive en su propia capa (Shadow DOM): los estilos de tu sitio no lo rompen. Personalízalo con estas variables en tu CSS:

CSS 
:root {
  --bsw-primario: #1d2b53;        /* botones y selección */
  --bsw-primario-texto: #ffffff;
  --bsw-fondo: #ffffff;
  --bsw-texto: #1d2b53;
  --bsw-suave: #fffaf0;           /* fondos de resumen */
  --bsw-borde: #e7e2d6;
  --bsw-radio: 22px;
  --bsw-fuente: "Nunito", sans-serif;
  --bsw-fuente-titulo: "Baloo 2", sans-serif;
}

¿Varios médicos en tu clínica? El widget los lista para que el paciente elija. Para abrir la agenda de uno en concreto usa data-doctor="ID" en el botón. Para cambiar el nombre que sale arriba de la ventana, agrega data-titulo="Mi consultorio" al script.

Datos prellenados

Si tu web ya conoce al paciente (por ejemplo, llenó un formulario de contacto), pásale sus datos al widget para que no los escriba dos veces. Con atributos en el botón o desde JavaScript:

HTML / JS 
<a href="#" data-besalud="agendar" data-email="ana@correo.com"
   data-motivo="Control de crecimiento">Agendar</a>

BeSalud.abrir("agendar", {
  doctor: "ID_DEL_MEDICO",           // opcional
  email: "ana@correo.com", nombre: "Ana", apellido: "Gómez",
  telefono: "3001234567", motivo: "Control de crecimiento"
});

Eventos

El widget avisa a tu página lo que pasa, para que midas conversiones (Google Analytics, Meta Pixel) o muestres tu propio mensaje. Los eventos llegan a window y no llevan datos personales del paciente.

JS 
window.addEventListener("besalud:cita-confirmada", (e) => {
  // e.detail = { consultorio, referencia, medico, fecha, hora, abono }
  gtag("event", "cita_agendada", { value: e.detail.abono, currency: "COP" });
});

// O con la función del widget (devuelve otra para dejar de escuchar)
const dejar = BeSalud.on("pago-fallido", (d) => console.log(d.estado));
Eventos del widget
EventoCuándo
besalud:listoEl widget cargó y window.BeSalud ya existe.
besalud:abierto / besalud:cerradoSe abrió o se cerró la ventana de la agenda.
besalud:sesion-iniciadaEl paciente entró o creó su cuenta (nuevo: true).
besalud:turno-apartadoEligió horario; se le guarda mientras paga.
besalud:cita-confirmadaEl abono se aprobó y la cita quedó confirmada.
besalud:pago-fallidoPago rechazado, vencido o con conflicto de horario.
besalud:cita-canceladaEl paciente canceló desde "Mis citas".

Referencia de la API

Si prefieres construir tu propia interfaz (React, una app móvil, WordPress…), usa la API REST. Todas las respuestas son JSON.

URL base
https://api.besalud.co/api/v1/c/{consultorio}
Origen
Las peticiones deben salir del navegador desde un dominio autorizado de tu consultorio (cabecera Origin).
Sesión del paciente
POST /sesion o POST /pacientes devuelven un token. Envíalo como Authorization: Bearer <token>. Dura 2 horas y solo sirve en tu consultorio.
Reintentos seguros
En POST /citas envía Idempotency-Key: <id único por intento> (8 a 64 caracteres). Si la red falla y repites la petición con la misma clave, recibes la misma reserva (cabecera Idempotent-Replayed: true) en vez de apartar otro horario. La clave dura 24 horas.
Endpoints de la API de consultorios
MétodoRutaQué haceSesión
GET/Nombre del consultorio, sus médicos activos (precio, abono, política de cancelación) y el tipo de pago.No
GET/disponibilidad?doctorId=Días y horas libres de los próximos 30 días.No
POST/pacientesRegistra al paciente y devuelve su sesión.No
POST/sesionInicia sesión con correo y contraseña.No
GET/yoDatos del paciente de la sesión.Sí
POST/citasAparta el horario y devuelve cómo pagar el abono. La cita nace cuando el pago se aprueba.Sí
GET/pagos/{referencia}Estado del abono: ESPERANDO_PAGO, PROCESANDO, CONFIRMADA, RECHAZADA, CONFLICTO o EXPIRADA.Sí
GET/citasCitas del paciente con los médicos de tu consultorio.Sí
POST/citas/{id}/cancelarCancela la cita; indica si se devuelve el abono según tu política.Sí

Con Wompi, el paciente vuelve a retorno con ?bs_ref=REFERENCIA&id=TRANSACCION. Consulta GET /pagos/{referencia}?id=TRANSACCION: BeSalud verifica el pago directamente con Wompi.

Errores

Todos responden { "error": "mensaje para mostrar al paciente" }.

Códigos de error
CódigoCuándo
400Datos incompletos o inválidos (fecha, motivo, contraseña débil…).
401Sin sesión o sesión vencida: vuelve a llamar a /sesion.
403El consultorio no existe, está inactivo o la petición no viene de su dominio.
404El médico, la reserva o la cita no son de tu consultorio.
409El horario se acaba de ocupar o el correo ya tiene cuenta.
422Reusaste una Idempotency-Key con otros datos.
429Demasiados intentos; espera unos minutos.

Seguridad

  • Sin claves en tu web. No hay llaves secretas que publicar: el acceso se controla por dominio autorizado y por la sesión del paciente.
  • Datos aislados. Tu consultorio solo ve sus médicos, sus reservas y las citas que el paciente tiene contigo.
  • Sesión acotada. El token del paciente no abre el portal de BeSalud ni sirve en otro consultorio.
  • Pagos verificados. El abono se confirma con la pasarela desde el servidor, nunca con lo que trae la URL.
